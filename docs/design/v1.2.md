# Sleuthline 1.2 — design (draft for review)

Status: **draft**, to be reviewed before any code. Builds on 1.1 (sources of a case, step requirements, coverage, conservation, timestamp provenance).

Goal of 1.2: **several hosts in one case**, analyzed together. An intrusion rarely stays on one machine: on DFIR Madness Case 001 the attacker brute-forced the domain controller, then moved by RDP to the workstation. With one host per case, the DC was only visible through the network capture, and the agent could only *infer* its compromise. With both hosts in the case, the same `coreupdater.exe`, the same C2 and the RDP hop can be shown on both sides, with evidence from each host.

Inputs: the *Known limitations* of the README ("One host per case"), the Case 001 runs (the DC disk image and memory image are public and were not used), the third external review.

Out of scope for 1.2: computing clock offsets between sources (`clock_offset_s` stays reserved, 2.0), the evidence & hypothesis graph (2.0), Linux and macOS hosts (only Windows hosts parsed with the current tools).

---

## 1. Layout of a multi-host case

```
<case>\
  hosts\
    DESKTOP-SDN1RPT\        one folder per host = exactly a 1.1 case
      kape\                 KAPE collection (or raw\, or at the root of the host folder)
      memory\               memory image of this host (optional)
      pcap\                 capture taken on this host only (optional, rare)
    CITADEL-DC01\
      kape\
      memory\
  pcap\                     captures of the case (tap, firewall, span port): seen by every host
  inventory\  parsed\  db\  analysis\     results at case level
```

- **A host folder is a 1.1 case.** Inventory, parsing and normalization of a host reuse the 1.1 code unchanged, with the host folder as the "case". This keeps the risk low: a host is processed exactly like today's tested cases.
- **Host id** = name of the folder (letters, digits, `-`, `_`). The real host name read from the artifacts (registry `ComputerName`, memory `COMPUTERNAME`) is shown next to it; a mismatch is reported, not corrected.
- **Case-level captures** (`<case>\pcap\`) are parsed once, at case level (a network-only "host" named `network`). A capture inside a host folder belongs to that host.
- **No `hosts\` folder = single-host case**, processed exactly as in 1.1 (host id = name of the case). No change for existing cases, commands or reports.

## 2. Processing per host, then one case database

| Step | Single host (1.1, unchanged) | Multi-host (1.2) |
|---|---|---|
| inventory | `<case>\inventory\` | `hosts\<h>\inventory\` for each host, plus `<case>\inventory\hosts.json` (hosts, their sources, real host names) |
| parse | `<case>\parsed\` | `hosts\<h>\parsed\` for each host; `<case>\parsed\` for the case-level captures |
| normalize | `<case>\db\case.duckdb` | `hosts\<h>\db\case.duckdb` for each host (with **its own** ActiveTimeBias), then **merge** into `<case>\db\case.duckdb` |
| analyze / report | one database | the merged database |

`sleuthline.ps1 all|inventory|parse|normalize <case>` detects `hosts\` and loops over the hosts; `--host <h>` limits a command to one host (e.g. re-parse the DC only). Parsing stays sequential, one host after another (the tools already use the CPU; two KAPE parsings in parallel would mostly fight for the disk).

### The merge (new: `3_normalize/merge.py`)

Builds the case database from the host databases, without re-reading any tool output:

- **Common tables** (`timeline`, `detections`, `hash_hits`, `coverage`, `conservation`, `sources`, `jobs`, `artifact_summary`): `UNION ALL BY NAME` of the hosts, with a new column **`host_id`**.
- **References** become `<host>:<output>#<record>` (e.g. `CITADEL-DC01:evtxecmd/evtxecmd_0.csv#40866`); `src_file` gets the same prefix. A single-host case keeps today's references (no prefix), so the 1.0 / 1.1 golden references stay valid.
- **Raw tables**: one schema per host (`raw_desktop_sdn1rpt.vol_pslist`), plus a view `raw.<table>` = union of the hosts that have the table, with a `_host` column. The agent keeps querying `raw.<table>`; `get_evidence` resolves a reference through `sources.raw_table`, which points to the host schema.
- **Meta**: `hosts` (id, real name, sources, ActiveTimeBias, collection integrity of each host), `merged_at_utc`, SHA-256 of each host database.
- **Conservation of the merge**: rows per host and table before = rows after, recorded in `conservation` (check `host_to_case`).
- **Disk space**: the merged database is a copy (about the sum of the host databases). Accepted: one self-contained file, hashed in the report, is simpler to keep as evidence than a database that attaches others. To be measured on Case 001 (two hosts + capture).

### Time

Each host's local-time sources are converted with that host's ActiveTimeBias (already the case per host database). The timeline is in UTC for every host. Clock offsets between hosts or with the capture are not computed (2.0); the playbook asks the agent to check them on pivots (same event seen on two hosts or on the wire), as it did on Case 001.

## 3. Analysis

### Which steps run per host, which once for the case

Running every step on every host multiplies the cost by the number of hosts. Running every step once on all hosts in one conversation fills the context with several hosts at the same time. The playbook therefore declares a **scope**, on the line after the title (next to `Requires:`):

| Step | Scope | Why |
|---|---|---|
| 1 System context, 2 Triage of detections, 3 Program execution, 4 Memory, 6 Persistence, 7 Accounts, 9 User activity, 10 Web browsing, 11 Defense evasion | `Scope: host` | host artifacts; run once per host, with the host in the prompt and the queries filtered on `host_id` |
| 5 Network traffic | `Scope: case` | the capture sees every host |
| 8 Remote access and lateral movement, 12 Collection and exfiltration, 13 Timeline and correlation, 14 Summary | `Scope: case` | the point is the links between hosts |

- `Scope:` missing = `case` (a custom playbook keeps working as in 1.1).
- A host step is recorded per host: `steps["3@CITADEL-DC01"]`, with its own status, duration and summary. `Requires:` applies per host (step 4 is `not_applicable` for a host without a memory image).
- The **case steps** get a short digest of the host steps (findings, IOCs, timeline events of each host) at the start, so that the correlation starts from what each host showed.
- Single-host case: every step runs once, as in 1.1.

**Expected cost** (Case 001, two hosts + capture, from the 1.0 full run at 11.76 USD): 9 host steps × 2 + 5 case steps ≈ 1.6 × the single-host run, so **about 18–20 USD**. The `max_billed_tokens_per_run` cap still applies.

### Findings, events, IOCs

- Every finding, timeline event and IOC gets `hosts` (list of host ids), filled by the program from the evidence references, not declared by the model.
- **Evidence policy**: unchanged rules. Two hosts are two independent sources (the disk of the DC and the disk of the workstation); the capture stays one source. A cross-host finding (e.g. the RDP hop: 4624 on the workstation, outbound RDP traces on the DC, flow in the capture) is therefore well corroborated.
- New agent tool `hosts()`: list of hosts, their sources, real names, time bias and coverage summary.

## 4. Report

- **Cover / About**: "Systems analysed: 2 (DESKTOP-SDN1RPT, CITADEL-DC01) and network captures" instead of "Main system".
- **1.2 Sources analysed**: one block per host (collection, memory image, integrity), then the case-level captures.
- **3.1 Attack timeline**: new **Host** column; it is the main view of the movement between machines.
- **3.3 Affected systems**: the hosts of the case first (with their sources and the number of findings per severity), then the other systems seen in the artifacts.
- **4. Technical analysis**: one sub-section per host (host steps), then one for the case steps.
- **Appendices**: steps per host, coverage per host, traceability with the SHA-256 of each host database and of the merged database.
- Single-host case: report as in 1.1.

## 5. Tests

- Layout: a case with `hosts\A` (KAPE) and `hosts\B` (memory only) and `<case>\pcap\`: inventory per host, `hosts.json`; a case without `hosts\` is unchanged.
- Merge: two small host databases (same raw table name, different columns) → `host_id` on every common table, prefixed references, `raw.<table>` view with `_host`, `get_evidence` on a prefixed reference, conservation `host_to_case` ok; one row removed → `fail`.
- Scope: `Scope: host` step run once per host (mock provider: call count), `Requires: memory` skipped only for the host without memory, `Scope: case` step once; missing line = `case`.
- Evidence policy: one finding with evidence from two hosts = two sources.
- Report: Host column, hosts in the affected systems, no `hosts` wording in a single-host case.
- The 1.1 tests keep passing (single-host path unchanged).

## 6. Validation

DFIR Madness Case 001 with the **two hosts**: workstation (KAPE + memory, as in the full 1.0 run), domain controller CITADEL-DC01 (KAPE collection of the public E01 image + its memory image), and the capture at case level. Compared with the 1.0 full run: what is now proven on the DC side (RDP brute force received, `coreupdater.exe` and its service on the DC, RDP session to the workstation), duration and cost.
